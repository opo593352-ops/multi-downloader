# 发布说明 / Release Notes

版本 **v1.2.0**（2026-10-25）

---

## 一、这个包是什么

一个 Windows 单文件下载器，四个功能：

| 功能 | 命令 | 依赖 |
|---|---|---|
| 抖音视频（含 4K / 图文） | `video` | 自带 Chrome/Edge |
| 音乐三平台横评（酷我/QQ/网易云） | `music` | 无 |
| **站点视频（B站/优酷/腾讯/芒果）** | `sites` | **yt-dlp + ffmpeg** |
| 知乎文章 → MD/TXT/DOCX | `zhihu` | 自带 Chrome/Edge |
| 通用网页抓取（测试） | `grab` | 自带 Chrome/Edge |
| 激活授权 | `license` | 无 |

图形界面 `下载器UI.exe` 把四个功能做成四个标签页，双击即用。

## 二、发布包结构（重要）

```
发布目录/
├── 下载器UI.exe        ← 双击这个（62 KB）
├── 下载器.exe          ← 引擎，四个功能都在这（≈89 MB）
├── ffmpeg.exe          ← 合并音视频用（≈88 MB）
├── README.md
├── 使用说明.txt
├── 发布说明.md          ← 本文件
└── 免责声明.md          ← 用户协议/免责声明（首次启动强制同意）
```

**三个文件必须在同一目录。** UI 会自动找同目录的 `下载器.exe`，
引擎会自动找同目录的 `ffmpeg.exe`。

### 关于 yt-dlp

`sites`（站点视频）功能需要 yt-dlp，它**没有**打进包里，原因见下节。
用户需要自己装一次，任选其一：

```powershell
pip install -U yt-dlp
```

或下载 `yt-dlp.exe` 放到发布目录（引擎会自动识别同目录的 `yt-dlp.exe`）。

**首次使用 sites 功能时，如果没装 yt-dlp，程序会打印明确的安装指引**，
不会静默失败。

## 三、许可证义务（发布前必读）

### ffmpeg 是 GPLv3

包里的 `ffmpeg.exe` 来自 [gyan.dev](https://www.gyan.dev/ffmpeg/builds/) 的
essentials build，配置里带 `--enable-gpl --enable-version3`，因此：

**它是 GPLv3 软件。** 你把 `ffmpeg.exe` 一起分发，就承担 GPLv3 的义务。

合规做法（任选其一）：

| 方案 | 做法 | 适用 |
|---|---|---|
| **A. 附源码**（推荐） | 发布包里加一个 `ffmpeg-source.txt`，写明版本 7.1、构建来源 gyan.dev、源码地址 https://ffmpeg.org/releases/ ，并声明「本程序包含 GPLv3 的 FFmpeg，其源码可从上述地址获取」 | 最省事，合规 |
| **B. 换成 LGPL 构建** | 改用不带 `--enable-gpl` 的 ffmpeg 构建（如 BtbN 的 `ffmpeg-master-latest-win64-lgpl`） | 想避开 GPL 传染 |
| **C. 不打包 ffmpeg** | 让用户自己装，程序探测 PATH / 用户目录 | 包最小，用户最麻烦 |

**注意**：`下载器.exe` 本身（Node SEA）与 ffmpeg 是**两个独立进程**，
通过命令行调用，不链接、不派生。这种「程序调用外部工具」的用法通常被认为
不构成衍生作品，但 GPL 的边界有争议。**最稳妥是方案 A 附上源码声明。**

本项目自身代码（`.mjs` / `.cs`）不强制开源，但如果你愿意，开源是最干净的。

### 各组件许可证速查

| 组件 | 许可证 | 分发要求 |
|---|---|---|
| Node.js 运行时（内嵌在 下载器.exe） | MIT | 附版权声明 |
| FFmpeg | **GPLv3** | 附源码或书面提供源码的承诺 |
| yt-dlp（未打包） | Unlicense | 无 |
| 本项目代码 | 你决定 | — |

Node.js 的 MIT 声明在 `node.exe` 里已内嵌，但稳妥起见建议在发布页注明
「本程序内嵌 Node.js 运行时（MIT License）」。

## 四、已知限制

### 站点支持

| 站点 | 状态 | 说明 |
|---|---|---|
| B站（普通视频） | ✅ 实测通过 | 1080p 需登录，4K 需大会员 |
| B站（番剧） | ✅ 支持 | 用 `--all-parts` 下整季 |
| 优酷 / 腾讯 / 芒果 | ⚠️ 视内容而定 | yt-dlp 提取器随站点改版会失效 |
| 抖音 | ✅ | 走独立引擎，不需要 yt-dlp |

**DRM 内容不在支持范围**。Netflix/Disney+ 这类有 Widevine 保护的内容，
常规手段拿不到，程序会明确报错而不是下出坏文件。

### 画质与登录

- 未登录时 B站最高 480p（1080p 要登录，4K 要大会员）
- UI 的「登录态」框填 `chrome`/`edge` 可以借用浏览器登录态，
  **但必须先把浏览器完全退出**——Chrome 运行时会锁住 cookie 数据库，
  yt-dlp 拷不出来。程序检测到这种情况会自动降级为「不用 cookie 重试」，
  并在日志里说明原因。

### CDN 回退

B站的视频流常指向第三方 CDN（如 `xxx.edge.mountaintoys.cn:4483`）。
某些网络到这些非标准端口会超时。程序会自动把 path 换到官方镜像重试：

```
原 CDN 不可达，尝试镜像...
✓ 改用镜像: upos-sz-mirrorcos.bilivideo.com
```

实测：原 CDN 完全不通的环境下，靠镜像仍能正常下载 1080p。

## 七、v1.2.0 新增功能

### 1. 音乐搜索过滤（格式 + 音质）

```powershell
# 只要 m4a，且码率不低于 128kbps
.\下载器.exe music search "雨爱" --format m4a --min-kbps 128

# 只要 mp3 和 flac
.\下载器.exe music search "雨爱" --format mp3,flac

# 体积不小于 2MB
.\下载器.exe music search "雨爱" --min-size 2048
```

UI 上在音乐页第二行：`格式 [MP3] [M4A] [FLAC]` + `最低码率 [不限/64/128/192/256/320]`。

**码率是估算值**（体积 ÷ 时长）。平台不给时长时该条记为 0kbps，
若同时指定了 `--min-kbps` 会被筛掉——避免把"算不出"当成"高码率"。

被筛掉的条目不会消失，JSON 里带 `filtered: true` 和 `filterReason`，
方便排查"为什么搜到了却选不了"。

### 2. 知乎导出三种格式

```powershell
.\下载器.exe zhihu "<url>" --format md,txt,docx     # 一次出三份
.\下载器.exe zhihu "<url>" --format docx            # 只要 Word
.\下载器.exe zhihu "<url>" --format txt             # 只要纯文本
```

UI 上在知乎页：`输出格式 [Markdown] [纯文本] [Word (docx)]`，可多选。

docx 是**零依赖手写生成**的（zip + OOXML），不引入第三方库，
避免 SEA 打包踩动态 require 的坑。实测 Word 打开正常：

| 验证项 | 结果 |
|---|---|
| Word COM 打开 | ✅ OPEN_OK |
| 段落数 | 322 |
| 字数 | 4916 |
| 页数 | 18 |
| 标题样式 | ✅ Heading1-3 生效 |

支持标题、段落、加粗、斜体、行内代码、有序/无序列表、引用、
代码块、分隔线。**图片在 docx 里是占位文字**（内嵌图片要写
relationship，成本高；需要图请用 md 格式）。

### 3. 通用网页抓取（测试）

```powershell
.\下载器.exe grab "https://example.com/article"
.\下载器.exe grab "<url>" --all -o D:\grab
.\下载器.exe grab "<url>" --images --min-w 800
.\下载器.exe grab "<url>" --json      # 只看结构，不落盘
```

抓什么：

- **正文**：用"文本密度"启发式（文字多、标签少 → 分数高），
  优先 `article` → 常见 content 容器 → 密度最高块 → body
- **图片**：含 `data-original` / `data-src` / `data-actualsrc` 等懒加载属性
- **链接**：去重后的绝对地址
- **元信息**：title / description / og:*

**这是通用工具，不含任何站点专属逻辑。** 定位是测试/调试：
验证连通性、检查防盗链、摸页面结构。遇到 403 / Cloudflare 时
用 `--headful` 手动过一次验证。

实测（知乎文章）：正文 3662 字、图片 6 张（成功 2、失败 1）、链接 173 条。

## 十一、激活（卡密）

**本版本发布时是未激活状态。** 用户首次使用需要激活。

### 未激活时能做什么

**所有下载功能都被拦截。** 只有授权相关命令可用。

| 功能 | 未激活 | 已激活 |
|---|---|---|
| 抖音视频 `video` | ❌ 拒绝 | ✅ 可用 |
| 音乐 `music` | ❌ 拒绝 | ✅ 可用 |
| 站点视频 `sites` | ❌ 拒绝 | ✅ 可用 |
| 网页抓取 `grab` | ❌ 拒绝 | ✅ 可用 |
| 知乎 `zhihu` | ❌ 拒绝 | ✅ 可用 |
| `license` 相关 | ✅ 可用 | ✅ 可用 |
| `--version` / `help` | ✅ 可用 | ✅ 可用 |

未激活时命令行返回 **exit code 2**，并打印：

```
╔═══════════════════════════════════════════════════════╗
║                    软 件 未 激 活                     ║
╚═══════════════════════════════════════════════════════╝

  状态  : 尚未激活
  机器码: 25C2B

  使用方法:
    1) 把上面的机器码发给卖家，换取激活码
    2) 运行:
         下载器.exe license activate "<激活码>"
```

UI 上点任何「开始」按钮会弹「需要激活」窗口，点确定直接跳到输入激活码。

**为什么保留 `license` 和 `help`**：不保留的话用户没法激活（死锁），
也没法看帮助。这两条是激活的入口，必须放行。

### 用户侧激活

```
菜单「授权」→「查看本机机器码」→ 发给卖家
菜单「授权」→「输入激活码」   → 粘贴激活码
```

命令行等价：

```powershell
.\下载器.exe license machine
.\下载器.exe license activate "<激活码>"
.\下载器.exe license status
.\下载器.exe license deactivate      # 清除激活（换机/测试用）
```

### 卖家侧发卡

用 **`内部工具\卡密生成器.exe`**（独立 EXE，**不在发布包里**）：

```cmd
卡密生成器.exe 25C2B            单张
卡密生成器.exe 25C2B -n 10      批量
卡密生成器.exe --verify <卡密>   校验
```

双击运行会进交互菜单，不用记命令。

详见 **`卡密系统说明.md`**。

### ⚠ 两个必须注意的点

**① 卡密生成器绝不能外发。** 它内含 SECRET，流出去等于授权系统作废。
`build-all.cmd` 已加防护，每次组装发布包会主动删掉它。

**② 发布前确认是未激活状态。** 检查方法：

```powershell
.\下载器.exe license status
# 应显示: 状态  : ❌ 未激活 (absent)
```

如果显示已激活，执行 `.\下载器.exe license deactivate`，
并确认 `%APPDATA%\UnifiedDownloader\license.txt` 已删除。

> 注意：激活记录存在 `%APPDATA%`，**打包时不会被打进去**。
> 但如果你自己机器上激活过，压包发给别人时对方是新机器，自然也是未激活。
> 真正要检查的是：发布目录里不要有 `license.txt`。

### 已知限制

- **一卡一机**：换机器需重新签发
- **重装系统会失效**：机器码由 hostname + CPU 型号生成，重装后 hostname 若变则失效
- **加内存/换硬盘不受影响**（刻意没把这两项算进机器码）
