## 二、卡密系统的处理（**重要**）

### 现状

**已停用，但代码保留。**

```js
// src/dev/gate.mjs
export const FREE_EDITION = true;   // ← 总开关
```

`assertFeature()` 直接返回放行。所有 9 个功能无条件可用。

### 为什么保留而不删

1. 两千多行代码，删了想加回来很难
2. 社区 fork 可能需要（比如公司内部部署要限人数）
3. **对普通用户零影响** —— 闸门关了，代码存在也不执行

### ⚠️ 密钥已公开，不要再指望它

`src/dev/secret.mjs` 顶部的 `SECRET` 已随源码公开。文件开头加了醒目警告：

> 如果你 fork 出去想重新做收费版：
> 1. 用你自己的随机源重新生成 SECRET
> 2. 重新生成 SCRAMBLED / PERM / IV / CT / TAG / DIGEST
> 3. 把 gate.mjs 的 FREE_EDITION 改成 false
> 4. **不要**把新的 secret.mjs 提交到公开仓库

### 卡密系统现在的完整能力（如果你要复活它）

v1.1.0 做的功能都还在：

- **累加续费**：年卡 364 天 + 月卡 30 天 = 394 天
- **防重复**：同一张卡只能激活一次（`used-cards.txt` 记指纹）
- **重装恢复**：删了 license.txt 也能恢复到历史最高到期日
- **绑机器码**：换机失效

这些都在 `src/dev/license.mjs`，逻辑完整，只是不再拦截。

## 三、三个 Bug 的根因（都值得记住）

### Bug 1：站点视频报「缺少授权凭据」

**现象**（测试者原话）：

```
sites 缺少授权凭据，任务无法开始
```

开源版明明关了闸门，为什么还报缺授权？

**根因**：`dev/gate.mjs` 有**两道**闸，我只关了第一道。

| 闸 | 函数 | 作用 |
|---|---|---|
| 第一道 | `assertFeature()` | 功能是否允许 |
| 第二道 | `tempWorkDir()` | 临时目录名必须带「票」 |

第二道是防破解设计：防止有人只改 `checkFeature()` 返回 `{ok:true}` 就绕过。
它要求 `shortTicket()` 返回 **64 位十六进制的票**，拼进临时目录名后回读核对。

我第一版返回 `{ok:true, ticket:null}` → `shortTicket()` 拿不到票 → 抛错。

**修法**：给开源版发一张形状合法的固定票。

```js
const FREE_TICKET = '0f3e9a7c1b42';   // 12 位十六进制

export function shortTicket(feature) {
  if (FREE_EDITION) return FREE_TICKET;
  ...
}
```

**为什么用固定值不用随机**：临时目录名要可预测，断点续传才能跨进程对上。

**教训**：改闸门类代码，必须把所有依赖"票"的地方都查一遍。
`grep -rn "ticket" src/` 是最快的办法。

### Bug 2：下载卡在最后一点（**最严重**）

**现象**：测试者等了 210 秒，卡在最后一点完全下不动。

**根因**：所有引擎的下载循环都没有**空闲检测**。

```js
const res = await fetch(url);              // ← 没有超时
for await (const chunk of res.body) { ... } // ← 没有"多久没收到数据"的判断
```

**关键认知**：`AbortSignal.timeout(N)` 只限制**总时长**，解决不了「卡在 99%」。

- 卡住之前都是正常速度 → 时间预算还够
- 卡住之后 `fetch` 只能等 TCP 自己超时 → 好几分钟

**唯一有效的判据是「多久没收到新字节」。**

**修法**：新建 `src/dev/dl.mjs`，三层保护：

| 层 | 作用 | 默认 |
|---|---|---|
| 连接超时 | 建连阶段 | 20 秒 |
| **空闲超时** | 连续 N 秒无新字节 → 中断 | **30 秒** |
| 总时长上限 | 单文件 | 30 分钟 |

中断时保留 `.part`，重跑自动续传。

**5 个引擎全部接入**：`music-dl` / `stock` / `douyin-dl` / `kuaishou-dl` / `video-dl`。

**验证方法**（假服务器模拟卡死）：

```js
// 服务器只发 100KB 就停住
res.writeHead(200, { "Content-Length": "5000000" });
res.write(Buffer.alloc(100000, 0x41));
// 之后不发任何数据，也不结束
```

实测：3 秒后中断（配的 3000ms），`code=ESTALL`，保留 100000 字节，续传后完整。

### Bug 3：包内缺 yt-dlp

**现象**（测试者日志）：

```
[缺少依赖] yt-dlp
yt-dlp 是解析引擎，必需。任选一种安装：pip install -U yt-dlp
```

**根因**：包里有 ffmpeg，但没 yt-dlp。站点视频直接不可用。

**修法**：
1. 下载 yt-dlp.exe（22.5 MB）放进 `发布/bin/`
2. `make-test-ff.sh` 加前置检查 + 冒烟测试（必须 `--version` 能跑）

包从 64.9 MB → **87.2 MB**。这是开箱即用的代价。

## 四、ffmpeg / yt-dlp 的处理（**新机制**）

### 两个位置

| 位置 | 用途 | 进 git？ |
|---|---|---|
| `发布/bin/` | 打包源 | ✗（`发布/` 整个排除） |
| `src/` | 开发调试副本 | ✗（`*.exe` 排除） |

**为什么 `src/` 也要放一份**：以前调试站点视频会去找 `发布/bin/` 的，
一旦 `发布/bin/` 被清理（`make-test-ff.sh` 会 `rm -rf` 目标目录），调试当场断。

现在 `src/` 自带一份，**任何地方双击 `src/下载器UI.exe` 都能直接跑**。

### 为什么不进 git

- clone 会变得极慢
- ffmpeg 84MB，接近 GitHub 单文件 100MB 红线
- 每次升级都要重提交 106MB，历史迅速膨胀

### 新克隆的人怎么办

```bash
node tools/取依赖.mjs
```

脚本行为：

| 命令 | 作用 |
|---|---|
| `node tools/取依赖.mjs` | 缺什么补什么（已存在且能跑的跳过） |
| `node tools/取依赖.mjs --force` | 全部重下 |
| `node tools/取依赖.mjs --check` | 只检查不下载 |

**关键设计**：不只判断"文件存在"，还会**真的跑一下** `--version`。
因为 0 字节的空壳、下载一半的残片都存在但不可用。

ffmpeg 是 zip，脚本用系统自带 `tar` 解压（Windows 10+ 的 bsdtar 能解 zip），
不引入第三方依赖。

**实测验证**：删掉 `src/yt-dlp.exe` 后跑脚本 → 自动下载 22.5 MB → 版本校验通过。

## 五、构建流程（已简化）

### 一条命令

```bash
bash 改完就跑这个.sh
```

做四件事：

```
0/4 检查依赖（缺了自动下载）
1/4 bash build.sh           → 发布/bin/ 的 exe
2/4 bash make-test-ff.sh    → 单包
3/4 同步 exe + 依赖到 src/
4/4 自检（8 项）
```

实测耗时 **69 秒**，全绿。

### 不再分 paid / free

v1.1.0 及更早要打两个包（正式版需激活 / 免激活版）。v1.2.0 开源后功能完全一样，
再分只会让测试者困惑（"我该下哪个？"）。

**现在只打一个包**：

```
发布/统一下载器-v1.2.0-一测（免费开源·含ffmpeg+yt-dlp）.zip   87.2 MB
```

### 自检 8 项

```
✓ 引擎版本 v1.2.0
✓ 下载器.exe / 下载器-beta.exe / 下载器UI.exe
✓ ffmpeg 可运行
✓ yt-dlp 2026.10.26
✓ 免激活可用（开源版预期）   ← 反向检查
✓ 发布包 87.2 MB
```

注意第 5 项是**反向检查**：开源版必须"未激活也能跑"。
如果哪天有人把 `FREE_EDITION` 改回 `false`，这里会立刻失败。

## 七、收款码

### 位置

菜单 **帮助 → 支持作者（打赏）**（放在下拉第一项）。

### 实现要点

图片作为**嵌入资源**打进 exe，不依赖外部文件：

```bash
csc -resource:donate.png,donate.png ...
```

代码里用反射按名字找：

```csharp
foreach (string nm in asm.GetManifestResourceNames())
    if (nm.EndsWith("donate.png")) { st = asm.GetManifestResourceStream(nm); break; }
```

**为什么嵌入而不放外部**：用户删了/搬走了文件，菜单就是空白。

### 文案基调

弹窗底部写明：

> 微信扫码 · 金额随意 · 不打赏也完全不影响使用

**不打赏不影响功能** —— 这句必须留着，否则会显得像强制收费。

## 十、已知限制（诚实记录）

### 1. 本地防重复挡不住删档

`used-cards.txt` 记录已用卡密，但**删掉 `%APPDATA%\UnifiedDownloader\` 整个目录就没了**。

- 能挡：手滑点两次、同一张卡发两个人（同机）
- 挡不住：用户删目录重来、一张卡发给不同机器

**要彻底解决只能上服务端**，但那会让软件变成"必须联网激活"。
现在开源免费了，这个问题**不再重要** —— 记录在此仅供将来参考。

### 2. 快手未端到端验证

快手首页/搜索页**强制登录**，无登录分享域需真实 photoId。
模块结构写全了（短链展开→SSR→GraphQL→登录态复用），但没真实链接验证过。

首次用必须 `--headful --profile` 盯着跑。

### 3. 歌单只支持网易云

酷我 `pl.svc` 只返回 `total=33` 但 `musiclist:[]`（曲目不下发），
QQ 要 uin+签名。两者都给了明确的不支持提示，不静默失败。

### 4. ffmpeg 是 GPL 构建

测试者日志里提醒过：

```
注意: 该 ffmpeg 是 GPL 构建，对外分发请注意许可证义务
```

`essentials_build` 是 GPL，随包分发按 GPL 要求需提供源码或源码链接。

**建议在 README 补一句**：

> 本软件内置 ffmpeg（GPL 构建），源码见 https://ffmpeg.org/download.html
