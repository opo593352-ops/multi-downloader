# src/ 里的 exe 是什么

> 这份说明解释 `src/` 根目录那 5 个 exe 的来历和用途。
> **`src/` 是开发目录，`发布/bin/` 才是唯一真源。**

---

## 一句话

`src/` 里的 exe 是**开发副本**，方便你在源码目录直接双击调试。
真正发布给用户的东西来自 `发布/bin/`，由 `build.sh` 生成。

---

## 现在有什么

| 文件 | 大小 | 是什么 | 能删吗 |
|---|---|---|---|
| `下载器.exe` | 88.9 MB | 引擎（正式构建） | 能，`build.sh` 会重建 |
| `下载器-beta.exe` | 88.9 MB | 引擎（内测构建，带 `INTERNAL_BUILD`） | 能，同上 |
| `下载器UI.exe` | 0.2 MB | 界面（8 个标签页） | 能，同上 |
| `ffmpeg.exe` | 83.6 MB | 音视频合并 | 能，`node tools/取依赖.mjs` 重下 |
| `yt-dlp.exe` | 22.5 MB | 站点解析 | 能，同上 |

**版本**：v1.2.0（开源免费版，无激活限制）
**构建时间**：2026-10-31

---

## 为什么 src/ 也要放 ffmpeg 和 yt-dlp

以前 `src/` 里没有这两个，调试站点视频时会去找 `发布/bin/` 的 —— 一旦 `发布/bin/`
被清理（`make-test-ff.sh` 会 `rm -rf` 目标目录），调试当场就断。

现在放了一份在 `src/`，**任何地方双击 `src/下载器UI.exe` 都能直接跑**，不依赖别的目录。

代价是磁盘上多占 106 MB（和 `发布/bin/` 各一份）。开发机不缺这点空间。

---

## 它们不进 git

`.gitignore` 里排除了：

```
ffmpeg.exe
yt-dlp.exe
```

原因：clone 慢、ffmpeg 接近 GitHub 单文件 100MB 红线、升级要重提交 106MB。

**新克隆的人跑一次**：

```bash
node tools/取依赖.mjs
```

自动下载到 `src/`，已存在的会跳过。

---

## 什么时候该重建

| 情况 | 做什么 |
|---|---|
| 改了 `src/engines/*.mjs` 或 `cli/*.mjs` | `bash build.sh` |
| 改了 `src/gui/Program.cs` | `bash build.sh`（会重编 UI） |
| 要发给测试者 | `bash make-test-ff.sh` |
| 只是想跑起来看看 | 不用重建，直接双击现有的 exe |

**注意**：改了 `.mjs` 源码但没跑 `build.sh`，双击 exe 跑的还是旧代码 ——
因为 exe 里是打包进去的快照，不会读旁边的 `.mjs`。

## 常见困惑

**Q: 为什么 `src/` 的 exe 和 `发布/bin/` 的 exe 一模一样？**

`build.sh` 直接输出到 `发布/bin/`，然后手工 `cp` 一份到 `src/`。
所以内容相同、SHA256 相同。**以 `发布/bin/` 为准**，`src/` 只是方便。

**Q: 我该双击哪个？**

`下载器UI.exe`（界面）。`下载器.exe` 是引擎，界面会自动调用它；
也可以命令行直接用（`下载器.exe --help`）。

**Q: 五个文件能分开吗？**

**不能。** 引擎和 UI 必须同目录（UI 靠 `FindEngine` 找引擎），
ffmpeg / yt-dlp 必须和引擎同目录（引擎在 exe 同级找它们）。

**Q: 卡密生成器呢？**

在 `发布/bin/卡密生成器.exe`。**不放进 `src/`，也绝不进 git** ——
它是发卡工具，公开等于把发卡权送给所有人。
（v1.2.0 开源后卡密系统已停用，这个工具只作历史保留。）
