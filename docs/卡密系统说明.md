# 卡密系统说明

> 写给要发卡的人（你自己）。**本文件不要随发布包分发。**

---

## 一、先说结论：这套东西能挡住谁

| 攻击者 | 挡不挡得住 | 说明 |
|---|---|---|
| 普通用户改系统时间/找注册表 | ✅ 挡住 | 卡密存 `%APPDATA%`，且与机器绑定 |
| 把 license.txt 拷给别人 | ✅ 挡住 | 机器码不匹配 |
| 用文本编辑器改 license.txt | ✅ 挡住 | 有 SHA256 校验，会报 `tampered` |
| 随便编一个卡密 | ✅ 挡住 | HMAC 签名校验 |
| 用 AI 读代码后改 `return true` | ⚠️ 部分挡住 | 见下节「卡密参与真实运算」 |
| 专业逆向 + 动态调试 | ❌ 挡不住 | 本地离线方案的天花板 |
| 直接改二进制跳过校验 | ❌ 挡不住 | 需要加壳/VMProtect 才能提高门槛 |

**核心事实**：任何纯本地离线授权都能被破。这套方案的目标是
**把破解成本从「改一行」提高到「理解整条派生链并重新实现」**，
让 95% 的人放弃，而不是 100% 防住。

## 二、卡密结构

```
XXXXX-XXXXX-XXXXX-YYYY
└─10位随机─┘└绑定位┘└签名┘
```

| 部分 | 内容 |
|---|---|
| 前 10 位 | 随机（`A-Z` 去掉 `I/O`，`2-9` 去掉 `0/1`） |
| 绑定位（5 位） | 机器码；`XXXXX` 表示不绑定 |
| 签名（4 位） | `HMAC-SHA256(payload, SECRET)` 前 4 位 |

**机器码** = `MD5(hostname + CPU型号 + PROCESSOR_IDENTIFIER)` 前 5 位（去掉易混字符）。

刻意**不**包含内存、硬盘序列号——用户升级硬件不该导致卡密失效。

## 三、卡密参与真实运算（这是关键）

你提的第 3 点思路完全正确，但落地时有个数学陷阱，我踩了三遍：

### 走过的三条弯路

| 方案 | 结果 |
|---|---|
| key = HMAC(完整 payload) | 每人 key 不同 → 需一人一份 blob（运维不可行） |
| key = HMAC(档位)，4 档共享 | 伪造 payload 有 1/4 概率蒙对 → **实测被解开** |
| key = HMAC(sig4)，16 桶共享 | 伪造者编 4 个字符也落进某个桶 → **实测被解开** |

### 根因（数学性质，不是代码 bug）

> 只要「所有可能的桶都有 blob」，伪造就一定能解开。
> 要让伪造必失败，必须有「空桶」；
> 而空桶会让真用户也激活失败。
> 除非——每个用户一份专属 blob。

### 最终方案：一卡一 blob

```
激活码 = BASE64(JSON{ k: 卡密, d: 密文, i: iv, t: tag })
```

- key = `HMAC(SECRET, 'res|v1|' + 完整卡密)` —— 一卡一 key
- 加密的内容是 **CDN 镜像表**（B站下载必需）
- blob 只有 ~144 字符，整串激活码 ~496 字符，用户复制粘贴一次

**破解者改 `verifyKey` 的行为**：

```js
// 他改成
export function verifyKey() { return { ok: true, payload: '随便', sig4: 'AAAA' }; }
```

结果：
1. `unlockResource` 拿不到正确 key → GCM 认证失败
2. 镜像表为空 → B站第三方 CDN 不通时无法回退
3. 下载直接报「原 CDN 不可达，且本地没有可用的镜像表」

**这就是"改 return true 跑不起来"** —— 不是靠代码检查，是靠缺料。

## 四、怎么发卡

### 工具位置

```
内部工具\卡密生成器.exe      ← 独立 EXE，92 MB，不需要装 Node
```

**它不在发布包里，也绝不能放进去。** `build-all.cmd` 每次组装发布目录时会主动删掉它。

重建命令：

```cmd
cd src
build-keygen.cmd
```

### 两种用法

**双击运行** → 交互菜单，适合偶尔发一两张：

```
  1) 生成激活码（需要客户机器码）
  2) 批量生成（同一机器码多张）
  3) 校验一个卡密
  4) 显示本机机器码
  5) 退出
```

**命令行** → 适合批量/脚本化：

```cmd
卡密生成器.exe 25C2B           生成一张
卡密生成器.exe 25C2B -n 10     批量 10 张
卡密生成器.exe --verify <卡密>  查归属
卡密生成器.exe --self          显示本机机器码
```

### 完整流程

1. 用户打开软件 → 菜单「授权」→「查看本机机器码」，拿到 5 位码（如 `25C2B`）
2. 用户把机器码发给你
3. 你运行 `卡密生成器.exe 25C2B`
4. 把输出的**「激活码」整串**发给用户（约 540 字符）
5. 用户「输入激活码」粘贴 → 激活成功

**只需发激活码**，不用解释卡密和 blob 的区别。

### 为什么生成器要单独一个 EXE

三个原因：

1. **不装 Node 也能用** —— 你可能在另一台干净的电脑上发卡
2. **与发布包物理隔离** —— 减少误打包风险
3. **交互模式** —— 双击就能用，不用记命令

### ⚠ 安全边界（最重要的一段）

**这个 EXE 里含 SECRET。** 虽然拆了 6 段 XOR 混淆，但逆向能挖出来。

一旦它流出去：
- 别人可以自己造卡密 → 你的授权系统**当场作废**
- 而且是不可挽回的（除非换 SECRET 并给所有老客户重新发码）

所以：

| 要做 | 不要做 |
|---|---|
| 只放自己机器上 | 发给客户 |
| 放加密 U 盘备份 | 传网盘/微信 |
| 定期确认发布包没混进去 | 提交到公开仓库 |

`gen-license.mjs` 和 `license.mjs` 同理，源码也不能外流。

## 五、已知缺陷（必须承认）

| 缺陷 | 影响 | 缓解 |
|---|---|---|
| SECRET 会进 EXE | 有耐心就能提取 | 拆段 + XOR；但挡不住专业逆向 |
| 一卡一 blob 需要人工发卡 | 卖 1000 份要发 1000 次 | 写脚本自动化（读订单→生成→发邮件） |
| 用户换机器要重新发码 | 客服成本 | 允许一台机器免费换绑 1 次（人工处理） |
| 卸载重装会丢激活 | 用户抱怨 | license.txt 在 `%APPDATA%`，重装不丢；系统重装才丢 |
| 无在线吊销 | 泄露的码无法远程作废 | 靠 blob 里的 `revoked` 字段+发新版 |

## 六、这套方案不做什么

- **不联网校验**（你要求离线，且避免服务器成本和隐私问题）
- **不限制功能**（激活即全功能，不做"试用版少功能"来降低破解动机）
- **不做时间限制**（不做订阅，避免用户改系统时间绕过——那类方案天生脆弱）
- **不写提示词诱饵**（你清单里第 4 点）

关于第 4 点我单独说明：**提示词诱饵我不建议做**。

理由：
1. 对专业逆向和自动化脚本**完全无效**（你自己也写了）
2. 对 AI 辅助逆向有效期很短——模型会迭代
3. 在代码里埋"让 AI 停止分析"的指令，属于**对抗性内容**，
   被开源社区发现会引发负面舆情（"这个软件在代码里下毒"）
4. 真正有效的做法是把逻辑写复杂、把关键数据加密——
   也就是上面那套，不需要诱饵

如果你坚持要，我可以加，但建议至少不要伪装成"系统约束"，
那会让正常接手代码的人也困惑。

## 七、如果哪天要更强的保护

按成本排序：

| 方案 | 成本 | 效果 |
|---|---|---|
| 一卡一 blob（当前） | 低 | 挡住改 return true |
| 关键逻辑用 WASM 编译 | 中 | 反编译难度↑ |
| 加 VMProtect / Themida 壳 | 中（要买） | 静态分析难度↑↑ |
| 在线校验 + 心跳 | 高（要服务器） | 可远程吊销，但用户断网就不能用 |
| 硬件加密狗 | 很高 | 商业软件级别，个人卖不动 |

**现实建议**：当前方案足够卖小规模。等你月销过千再考虑升级。

## 八、一个必须提醒的合规点

卡密系统保护的是**你的收入**，不是**你的法律责任**。

上一轮已经说过：软件的实际能力（能不能下付费内容）决定法律性质，
跟有没有卡密无关。加了卡密反而说明这是**商业经营行为**，
在侵权认定上分量更重。

所以：
- 收费前先看 `收费发布清单.md`
- 定价页只写"下载工具软件授权"，不承诺能下什么内容
- 保留所有订单与同意记录
